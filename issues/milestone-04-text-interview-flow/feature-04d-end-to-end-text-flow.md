# 04d - End-to-end text flow verification and documentation

Phase: 2  
Milestone: 04 - Text interview flow  
Type: Feature  
Status: Completed

## Summary

Verify the full M04 text interview flow end to end and update documentation.

This feature validates that the interview API, list/setup UI, and active interview UI work together:

```text
/interviews → /interviews/new → /interviews/{id} → answer questions → completed
```

It also documents the M04 interview API, persistence mapping, page flow, and stubbed question generation strategy.

## Problem and User Value

04a, 04b, and 04c implement the backend and frontend pieces of the text interview flow. 04d verifies that those pieces work together as a complete user journey.

This gives confidence that users can:

- Start a new interview
- Resume an active interview
- Answer text questions
- Complete an interview
- Return to the interview list
- Rely on persisted state across page reloads/navigation

It also documents the architecture and extension points for future M05 AI work.

## Risks and Decisions

Risks:

- Browser end-to-end testing may require additional test setup if not already present.
- Test data setup for invited/non-invited users may need helpers or fixtures.
- Direct Cosmos document inspection may be difficult in automated UI tests, so persistence should primarily be verified through reload/list/API-observable behavior.

Decisions:

- The main happy path verifies final-answer completion.
- Early completion through `POST /api/interviews/{id}/complete` is covered by 04a/04c behavior and does not need to be the primary 04d happy path.
- 04d verifies integration of existing features, not every API edge case.
- Full completed interview history/review remains out of scope until M06.
- Hardcoded test count numbers should not be included in acceptance criteria because the count will change over time.

## Notes

Main M04 user journey:

```text
/interviews
  → /interviews/new
  → POST /api/interviews
  → /interviews/{id}
  → POST /api/interviews/{id}/answers
  → next question
  → final answer
  → completed state
  → /interviews
```

The full flow should use a small `questionCount`, for example:

```json
{
  "role": "backend-engineer",
  "seniority": "senior",
  "topic": "dotnet",
  "interviewType": "technical",
  "questionCount": 3
}
```

For a `questionCount` of `3`, the third answer should complete the interview automatically. The test should not call the early complete endpoint after the interview is already completed unless specifically verifying the `409 Conflict` behavior.

M04 question generation is stubbed/hardcoded. M05 will replace or extend this through the question generation abstraction.
